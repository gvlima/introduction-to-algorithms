Suppose we are comparing implementations of insertion sort and merge sort on the same machine. For inputs of size n, insertion sort runs in 8n2 steps, while merge sort runs in 64n lg n steps. For which values of n does insertion sort beat merge sort?

- Step count for insertion sort algorithm: $8 n^2$ 
- Step count for merge sort algorithm    : $64 n \log_{2} n$

We wish to determine for which values of $n$ the inequality $8 n^2 < 64 n \log_{2} n$ holds.

$$
8 n^2 < 64 n \log_{2} n
$$

$$
\frac{8 n^2}{8 n} < \frac{64 n \log_{2} n}{8 n} \quad \text{(dividing both sides by } 8n\text{)}
$$

$$
n < 8 \log_{2} n
$$

This inequality has no closed-form algebraic solution, so we check integer values directly: it fails at $n = 1$ (where $\log_2 1 = 0$), holds from $n = 2$ through $n = 43$, and fails again from $n = 44$ on.
The insertion sort algorithm is faster when $2 \le n \le 43$, otherwise merge sort is faster, because $n \log_2 n$ grows asymptotically more slowly than $n^2$ the constants 8 and 64 only delay the crossover, they do not prevent it.
